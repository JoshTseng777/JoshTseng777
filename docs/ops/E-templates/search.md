# E1｜任務交辦範本：搜尋／探索型

> 30 秒摘要：這份範本用在「找某功能在哪」「這段邏輯在哪個檔案」「repo 裡有沒有已經做過 X」
> 這類搜尋/探索型任務。複製下面「範本本文」，把【】或＿＿＿填掉，整段貼給 subagent 就能用。
> 欄位設計與回報格式對齊 `C-model-dispatch.md`，「何時該停下來問使用者」對齊
> `D-judgment-rubrics.md` 第 3 節，不重複整段抄錄，只留一句判準提示。

## 這類任務常見的陷阱（填範本前先看一眼）

- 優先用 `Glob`/`Grep` 定位，或整個任務直接派 `Explore` 類型 agent；**不要**叫 subagent 用
  `Bash` 跑 `find`/`grep`/`cat` 掃整個 repo——這是 A 診斷點名的第一號浪費模式。
- 探索範圍不明確時（例如「這功能可能在好幾個地方」），先在交辦前問清楚要多廣：
  `quick`（單一目標、大概知道在哪）／`medium`（中等範圍、跨幾個檔案）／
  `very thorough`（完全不確定、要跨多個位置和命名慣例比對），不要自己假設一個範圍就派工。
- 回報時每一項結論都要附 `檔案:行號`，不要只寫「大概在某個檔案」這種無法覆核的說法。

## 範本本文（複製這段，填空後貼給 subagent）

```
【任務名稱／一句話目標】
＿＿＿（例：找出使用者認證的 token 過期邏輯在哪個檔案）

【目標與動機】
（不是只給步驟，要給前提——為什麼要找這個？找到之後要拿去做什麼？讓 subagent 判斷「找到」的
標準時有依據，而不是隨便回一個看起來像的結果）
＿＿＿

【已知背景／已排除的做法】
（已經確認過、不用重新摸索的資訊；已經找過但排除掉的位置或做法，避免 subagent 重工）
＿＿＿

【具體範圍】
- 這次任務包含：＿＿＿
- 這次任務不包含（scope 外，不要順便做）：＿＿＿
- 探索廣度：＿＿＿（quick / medium / very thorough，不確定就先問使用者，不要自己猜）

【建議 model 與推理強度】
日常定位用 Sonnet；大範圍/多檔案掃描用 Haiku 批次做，找到模式後再用 Sonnet 收斂結論；
若需要判斷「這是不是架構性的設計位置」再升 Opus/Fable。具體模型 ID 字串見 C 文件模型對照表，
這裡不重複寫死。
本任務指定：＿＿＿（這格留白等於沒指定，實際會落到 Agent 呼叫當下的預設值——沿用
subagent 定義裡設的 model，或繼承父層——不會自動幫你選對層級，交辦前務必填）

【驗收條件】
（可檢查、具體，不要用「找到了」「處理完」這種模糊詞）
- 每一個結論都附 `檔案:行號`。
- ＿＿＿（例：至少涵蓋 src/ 與 tests/ 兩個目錄；或「確認是唯一一處，還是有多處類似邏輯」）

【回報格式】
只回結論 + `檔案:行號`，硬上限 15 行；不要貼整段程式碼，只貼必要的單行引用；
若掃描結果很長，先存成檔案，回報時只給路徑。

【何時該停下來問使用者，不要自己往下猜】
若遇到以下情況就先回報問使用者，不要自己猜一個答案往下做：找到兩個以上都像是「答案」的
候選位置且無法判斷哪個才是使用者要的、或探索範圍本身就不明確（quick/medium/very thorough
沒講清楚）——詳細判準見 D 文件「3. 何時該停下來問使用者」。
```
