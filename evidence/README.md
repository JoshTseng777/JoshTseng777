# evidence/ 使用說明

> 30 秒摘要：這個資料夾用來存放「真實發生過」的 session 失敗片段，供 A（快速診斷）與 D（判斷力外化）
> 引用具體案例。**建立本說明時，資料夾是空的**——A 文件裡的診斷因此全部標記為「推測」，不是實錄。
> 之後每次你（使用者）或某個 session 遇到 Claude Code 犯錯、繞路、失焦，就照下面格式存一份進來，
> 累積到有素材後，下次維護（見 F）時把 A 從「推測」升級成「有實例引用」。

## 什麼值得存進來

只存**具體、可重現、有結論**的案例，不要存整段對話紀錄。三種值得存的情況：

1. **Token 浪費**：模型讀了不該讀的東西（整個大檔案、不相關目錄、reasoning 繞了很多圈才收斂）。
2. **失焦/繞路**：模型偏離原始任務、自己加了使用者沒要求的功能、或改錯了檔案。
3. **錯誤但看起來對**：模型自認完成，但輸出實際上是錯的（測試沒跑、假設當事實、編造了不存在的 API）。

## 檔案格式

每個案例存成一個檔案：`evidence/YYYY-MM-DD-短描述.md`，內容固定四段：

```markdown
# 案例：<一句話標題>

## 情境
（哪個任務、用了什麼 model/subagent、大概第幾輪出的事）

## 發生了什麼（貼關鍵原文片段，不要整段貼）
（貼真正出錯的那幾行輸出或工具呼叫，不是整份 transcript）

## 為什麼算失敗
（具體判準：例如「使用者沒要求卻改了 X」「測試從沒真的跑過」「引用了不存在的檔案路徑」）

## 建議修法（若你當下已經想到）
（可留白，之後維護時再補）
```

## 之後怎麼用

- A（`docs/ops/A-diagnosis.md`）維護時：先讀這個資料夾裡的所有檔案（一手材料，不要只看檔名），
  找出重複出現的模式，把「推測」升級成「引用 evidence/xxx.md」。
- 案例太多、太舊時：把已經吸收進 A/D 規則裡的案例移到 `evidence/archive/`，避免這個資料夾無限長大。
